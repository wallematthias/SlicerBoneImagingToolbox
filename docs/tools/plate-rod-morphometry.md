# Plate/Rod Morphometry

`Plate/Rod Morphometry` is the Slicer front end for the `plate-rod-thinning` core package. It runs topology-preserving plate/rod thinning, labels plate and rod skeleton elements, ports those labels back to the original trabecular thickness, and reports plate, rod, element, and junction measurements.

The Slicer module handles mask selection, segment dropdowns, background execution, output loading, 3D display, and result tables. The thinning and morphometry logic lives in:

https://github.com/wallematthias/bone-plate-rod-thinning

## When To Use

Use this tool when you have a trabecular bone segmentation and want to inspect or quantify:

- a one-voxel-thick plate/rod skeleton,
- full-thickness plate, rod, and junction labels,
- individual full-thickness trabecular elements,
- plate and rod volume fractions,
- plate and rod counts, thickness, spacing or length summaries,
- plate-plate, plate-rod, and rod-rod junction densities.

The method is an open, auditable plate/rod skeleton analysis. It should be reported with its explicit settings and treated as the documented toolbox method.

## Inputs

- `Bone segmentation`: binary trabecular bone mask, labelmap, or segmentation node. If a segmentation node is selected, choose the exact segment in the adjacent `Segment` dropdown.
- `Trabecular compartment mask`: analysis region used for density-normalized measurements. This may be a labelmap, scalar mask, or segmentation node with a selected segment.

For typical HR-pQCT trabecular analysis, use the segmented trabecular bone as `Bone segmentation` and the trabecular compartment as `Trabecular compartment mask`. The two inputs must be in the same image geometry. Voxel spacing is read from the selected Slicer nodes.

## Controls

- `Slenderness`: optional plate-slimming setting before final plate/rod assignment. Keep this fixed across a cohort once chosen.
- `Max thinning iterations`: safety limit for iterative thinning.
- `Minimum plate voxels` and `Minimum rod voxels`: remove very small elements from the reported decomposition.
- `Use Metal acceleration on macOS`: uses the Metal skeletonization backend when available; otherwise the module falls back to the compiled CPU backend.
- `Output prefix`: prefix for loaded Slicer nodes and files generated by the background job.
- `Install / update compiled plate-rod core`: installs the published PyPI wheel and verifies that the compiled backend imports in Slicer Python.

## Outputs

After a successful run, the module loads a summary table and labelmaps into Slicer:

| Output | Meaning |
| --- | --- |
| `Skeleton` | Binary one-voxel-thick skeleton. |
| `Topology labels` | Local skeleton topology classes used for plate, rod, and junction assignment. |
| `Skeleton labels` | Skeleton map with plate, rod, and junction labels. |
| `Full-thickness labels` | Plate, rod, and junction labels ported back to the original trabecular thickness. This map is shown automatically in 3D with plates in blue and rods in red. |
| `Element labels` | Individual full-thickness trabecular elements after junction-aware plate/rod decomposition. |
| Summary table / `summary.json` | Scalar plate, rod, density, orientation, element-count, and junction measurements. |

When an output folder is used by the background run, the corresponding files are written as `skeleton.nrrd`, `topology_labels.nrrd`, `skeleton_labels.nrrd`, `full_thickness_labels.nrrd`, `element_labels.nrrd`, and `summary.json`.

## Basic Workflow

1. Open `Bone Imaging > HR-pQCT > Plate/Rod Morphometry`.
2. Use `Install / update compiled plate-rod core` if the status message says the core package is missing or outdated.
3. Select the bone segmentation and, for segmentation nodes, its segment.
4. Select the trabecular compartment mask and, for segmentation nodes, its segment.
5. Keep default decomposition settings for a first pass, then adjust cleanup settings only if needed for a predefined analysis protocol.
6. Click `Run plate/rod morphometry`.
7. Review the summary table and inspect `Full-thickness labels` in 2D and 3D.

The run is launched as a background process so Slicer remains responsive. The progress indicator and status text update while masks are exported, thinning runs, outputs are written, and the results are loaded back into the scene.

## Interpretation Notes

Report the mask definition, voxel size, core package version, thinning settings, slenderness setting, and cleanup thresholds with any analysis. Plate/rod results are sensitive to segmentation, compartment masks, and small-component filtering, so the same settings should be used consistently within a study.

The full-thickness label map is usually the most useful visual output for biological interpretation. The one-voxel skeleton is useful for checking topology and junction placement, but it can look sparse when viewed directly in 3D.
